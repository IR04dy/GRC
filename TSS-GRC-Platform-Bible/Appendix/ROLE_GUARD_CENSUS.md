# Role-guard census — what `hasAnyRole` actually authorises

Generated by `Appendix/scripts/role_guard_census.py` from the compiled `@PreAuthorize`
set (`RoleGuardConversionRatchetTest` → `target/role-guard-sites.txt`) joined against the
live `iam.roles` / `iam.role_permissions`. Do not hand-edit: the next run overwrites it.
Narrative belongs in the script.

⚠ **Every holder figure below was read from `TSS_GRC`.** The guard set is compiled from the
packaged jar and is the same everywhere; *who holds a role* is per database, and the two
can differ by **absence** as well as by holders — a role a pending migration has not
seated yet is missing from `iam.roles` on the deployed server while merely unheld in dev.
Re-run with `--database TSS_GRC_Deployment` to read the deployed server. (F2-259: this was hardcoded
to `TSS_GRC`, so section B2b's question — *does anybody hold this role?* — was being
answered about one database while the report read as a statement about the platform.)

`hasAnyRole('X')` tests for the granted authority `ROLE_X`. There is no fallback and no
PLATFORM_ADMIN bypass — `ModulePermissionEvaluator` is never called, so the platform
administrator passes a role guard only when the guard names a role they hold. A guard
whose every named role is absent from `iam.roles` is therefore not tight; if that is the
whole expression it is closed to everyone. Neither existing measurement can see that: the
authorization ratchet counts a role guard as guarded, and `GRANT_TIGHTNESS.md` joins
permissions, which a role-only guard names none of.

⚠ **Ghost roles cut both ways, and this report used to report only one of them.** When the
guard is `hasAnyRole(…dead names…) or hasAuthority('MODULE_ACTION')`, the dead names close
nothing — every caller arrives through the authority leg, and the endpoint is exactly as
wide as that permission. The ghosts then act as *camouflage*: the source reads like a
narrow, named audience while the real population may be twenty roles. Section B2 lists
these separately because they need the **opposite** fix from an attrition site — tighten,
do not open up. Read section B and B2 together before choosing a conversion target.

## B2. Pure role guards left admitting PLATFORM_ADMIN alone — by attrition

These are section B one notch weaker, and they are where this platform actually sits.
The guard names several roles; all but `PLATFORM_ADMIN` are absent from `iam.roles`; so the
feature is administrator-only, and the persona the module was built for cannot use it —
silently, because a 403 from a role guard is indistinguishable from a 403 that was meant.

Guards that name `PLATFORM_ADMIN` **and nothing else** are excluded: that is a stated
decision (settings reset, token revocation, platform administration) and belongs in a
different conversation. The distinction is invisible in the code, which is why it is
computed here rather than eyeballed.

## B2b. Effectively PLATFORM_ADMIN-only — by HOLDER attrition (F2-253)

Section B2 asks whether a named role **exists**. This one asks whether anybody **holds**
it, which is the question `hasAnyRole` actually puts: it tests for the granted authority
`ROLE_X`, and a role assigned to no user grants it to nobody. A guard naming four roles of
which only `PLATFORM_ADMIN` is held is administrator-only in exactly the way B2 describes —
and B2 reported none of these, because every name in them is present in `iam.roles`.

An administrator can assign the missing role without a new jar, which is what separates
this from section B. That is a remedy, not a defence: as shipped and as seeded, the persona
each of these features was built for cannot use it, and nothing in the platform says so.

## B3. Wide despite dead role names — the camouflage sites

The inverse of B2, and the reason this report now prints both. Every site here recites at
least one role that cannot be granted, yet is fully reachable, because a
`hasAuthority('MODULE_ACTION')` leg admits everyone holding that permission. The role names
contribute nothing except a misleading impression of narrowness. **The holder count is the
real audience** — compare it against what the endpoint's own comment claims, because that
is where the two disagree.

None. *(This bucket has fired before — see the note below — so an empty section here
means the pattern is absent, not that the detector is broken.)*

**Provenance of this section.** `BoardPackController#list`/`#get` (F2-05 slice 5) were the
first instance: five ghost roles plus `REPORTING_READ`, an authority **20 roles hold,
including `VIEWER`** — directly beneath a comment stating reads are for "a board/governance
audience, not any authenticated principal". Live: `viewer` read all 16 board packs, 200.
Until that slice this script bucketed those sites as *PLATFORM_ADMIN-only by attrition* —
it checked whether an authority leg was **dead** but never whether one was **alive** — and
that miscount is what sent the slice in expecting a lockout. Fixed to
`ADMIN:READ`/`ADMIN:WRITE`; the detector was re-verified by replaying the pre-fix guard
through it, which is why the count below can be trusted when it reads zero.

## F. Permission guards no active user can satisfy (F2-313)

Every section above is about **role** guards, because that is what this report was built
to track. `hasPermission` is F2-05's ratified **destination**, and the question B2b puts to
a role guard — *can anybody satisfy this today?* — had never been put to a permission one.
So the census measuring the conversion backlog was blind to the half it converts into.

A `hasPermission` guard gets **no** `PLATFORM_ADMIN` bypass from the evaluator's own
logic — the bypass is in code, ahead of it — so a pair with no active holder leaves its
routes reachable by a platform administrator and nobody else, exactly as B2b describes.

⚠ Read this section against the database named at the top. A pair unheld here may be held
on the deployed server and vice versa (F2-259).

weight: a pair guarding one endpoint is a feature nobody can use, and one guarding a
module's whole surface closes every screen in it.

There are two kinds and only one needs a jar. Present here:

* **7 granted to a role that exists and is seated in nobody.** An administrator
