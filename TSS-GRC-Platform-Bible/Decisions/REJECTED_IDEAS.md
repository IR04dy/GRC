# Rejected Ideas

| Idea | Decision | Why |
|---|---|---|
| Immediate microservices rewrite | Rejected | Boundaries are not mature; creates distributed failure and reporting complexity |
| Customer-specific forks | Rejected | Unsustainable upgrades, security fixes and support |
| UI-only module licensing | Rejected | Does not enforce security or contract |
| Separate framework modules for every regulator | Rejected | Duplicates controls and assurance; use versioned content packs |
| One mega navigation tree | Rejected | Overwhelms occasional users and exposes implementation structure |
| Generic status transition APIs | Rejected | Cannot safely enforce decision-specific authority and evidence |
| AI compliance verdicts | Rejected | Legal/accountability risk and false confidence |
| Database-per-module immediately | Rejected | Premature operational complexity |
| One universal GRC object | Rejected | Erases domain invariants and ownership |
| Per-seat pricing for all contributors | Rejected hypothesis | Discourages first-line participation; validate outcome/scale pricing |
| “Compliant by using TSS” marketing | Rejected | Platform supports compliance operations; customer control effectiveness remains contextual |
