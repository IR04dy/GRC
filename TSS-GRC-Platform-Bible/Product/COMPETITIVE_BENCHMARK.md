# Competitive Benchmark and Design Implications

## Comparison rule

This benchmark uses public vendor material to identify patterns. It is not a procurement evaluation or assertion of complete feature parity.

| Product/pattern | What the market values | TSS implication |
|---|---|---|
| ServiceNow IRM | common platform, mapped regulations/controls, continuous monitoring and remediation | make the evidence/control graph operational; connect to services and changes |
| Archer | configurable, holistic risk across internal and third-party domains | preserve configurable taxonomies without creating an administrator-only product |
| MetricStream | connected product lines, common controls and regulatory change | one control tested once with visible reuse; package lines on one kernel |
| OneTrust | purpose-built privacy/third-party workflows and shared trust data | make party, processing and data relationships first class |
| AuditBoard | connected audit-risk-compliance and approachable collaboration | strengthen audit experience and first-line task simplicity |
| Atlassian JSM | intuitive intake/queues, automation, change/deployment context | simplify My Work and link changes to CI/CD/services |
| Microsoft Power Platform | managed base/app solution layering and dedicated package lifecycle | manifest-driven kernel/package dependency and independent environments |
| Salesforce | source-driven managed packages, declarative dependencies and versioning | treat commercial modules as installable release artifacts |

## Where TSS can win

- Arabic-first professional UX;
- Saudi regulatory content and implementation playbooks;
- one evidence graph across NCA, SAMA, PDPL, BCM and enterprise risk;
- private/on-prem/Saudi-cloud deployment choice;
- package pricing that allows one-module entry;
- bilingual board/regulator evidence;
- faster implementation through opinionated Saudi templates.

## Where TSS currently loses

- assurance reputation and installed customer references;
- consistency and simplicity of experience;
- package lifecycle and dependency management;
- continuous external signals/connectors;
- enterprise-scale operational evidence;
- ecosystem, marketplace and implementation partners;
- documented accessibility and security assurance.

## Product-design lessons

1. Copy ServiceNow's connected context, not its administrative complexity.
2. Copy Archer/MetricStream configurability, not uncontrolled configuration debt.
3. Copy OneTrust's purpose-built guided workflows, not product sprawl.
4. Copy AuditBoard's practitioner usability and connected assurance.
5. Copy Atlassian's queues, templates and automation clarity.
6. Copy Microsoft/Salesforce package discipline, not their platform lock-in.
