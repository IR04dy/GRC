# 05 - Project Risk Register
> **HISTORIC — point-in-time snapshot (all files 2026-04-30). Not a statement of current state.**
> For what the platform is today read [`CLAUDE.md`](../../CLAUDE.md) and [`PROJECT_CHRONICLE.md`](../../PROJECT_CHRONICLE.md); for measured figures, [`MEASURED_BASELINE.md`](../../TSS-GRC-Platform-Bible/Appendix/MEASURED_BASELINE.md). Kept for provenance. *(W0-6)*


Risks to the TSS GRC Platform implementation project itself (not GRC content risks). Reviewed at the start of each sprint.

---

| ID | Risk | Likelihood | Impact | Score | Mitigation | Owner |
|---|---|---|---|---|---|---|
| PR-001 | **SQL Server Express 10 GB limit reached in production** — If a customer generates more audit log data than estimated, the DB may hit the 10 GB cap, causing write failures. | Medium | Critical | HIGH | Monthly archival job moves audit logs > 12 months to archive table. Storage monitoring alerts at 8 GB. Upgrade path to SQL Server Standard documented. | DB Lead |
| PR-002 | **Arabic translation gaps at launch** — UI strings added late in a sprint may not have Arabic translations, creating a mixed-language experience. | High | High | HIGH | Arabic translation is part of the Definition of Done. `translations.js` must have both `en` and `ar` keys before a PR is merged. | Frontend Lead |
| PR-003 | **JWT secret key exposure** — If `grc.jwt.secret` is committed to source control or exposed in logs, all issued tokens can be forged. | Low | Critical | HIGH | Secret injected via environment variable only (`${JWT_SECRET}`). Never hardcoded. `.gitignore` covers `.env` files. Secret scanning in CI pipeline. | Security Lead |
| PR-004 | **Regulatory framework content accuracy** — Seeded control frameworks (NCA ECC, ISO 27001, PDPL) may contain errors or outdated control text, leading to incorrect compliance assessments. | Medium | High | HIGH | Controls reviewed by Compliance SME before seeding. Source documents cited in `R__seed_controls.sql` comments. Annual update cycle defined. | Compliance SME |
| PR-005 | **Cross-module risk linkage failures** — If a module event (e.g. `DataBreachConfirmedEvent`) fails silently, the linked risk is never created, breaking the unified risk view. | Medium | Medium | MEDIUM | All event listeners wrapped in try-catch with error logging. Integration tests verify end-to-end event → risk creation flow. | Architect |
| PR-006 | **OpenPDF Arabic rendering defects** — Arabic text in exported PDFs may render with incorrect character ordering (logical vs visual order) or missing ligatures if Bidi support is not correctly implemented. | Medium | High | HIGH | PDF export tested with Amiri font and `java.text.Bidi` reordering in Sprint 2 Acceptance Criteria. Arabic legal documents used as reference test cases. | Frontend Lead |
| PR-007 | **Caffeine cache stale data in multi-node production** — If the platform is deployed to multiple app server nodes, each node has its own Caffeine cache, and updates on one node are invisible to others until TTL expires. | Low | Medium | LOW | Acceptable for v1.0 single-node Express deployment. Redis L2 cache documented as the upgrade path for multi-node. | Architect |
| PR-008 | **PDPC notification SLA breach (72 hours)** — A data breach detected late on a Friday may not be processed before the 72-hour regulatory clock expires if the on-call workflow is not defined. | Low | Critical | HIGH | Breach detection triggers immediate in-app notification AND email to DPO with 72h countdown. SLA check job runs every 15 minutes (`@Scheduled`). Escalation chain documented in operations runbook. | Privacy SME |
| PR-009 | **Module boundary leakage** — Developers may take shortcuts and access another module's repository directly (e.g. `RiskRepository` called from `ComplianceService`), violating module boundaries. | High | Medium | MEDIUM | Architecture rules enforced by ArchUnit tests (module-boundary test suite added in Sprint 1). Violations fail the CI build. | Architect |
| PR-010 | **Flyway migration conflicts** — Multiple developers modifying the same version number migration file will cause Flyway checksum failures in CI. | Medium | Low | LOW | Convention: each developer takes the next sequential version from a shared tracking spreadsheet. CI pipeline runs Flyway validate on every branch. | DB Lead |
